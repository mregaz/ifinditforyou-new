# IFINDITFORYOU 0 TO 1000 ROADMAP v1.0

## North Star

**Weekly Qualified Search Successes (WQSS):** completed real-user searches with at least one useful-result action or explicit useful rating.

Visits, impressions and registrations are supporting metrics, not proof of value.

## Phase A — 0→25 real users

**Duration:** 14 days
**Mode:** founder-led concierge validation

### Activities

- 20 problem interviews;
- 10–20 manual/assisted Vespa/moto searches;
- provider coverage benchmark on 20 queries;
- five-second test of positioning;
- 5 club/specialist partnership approaches;
- 3 consented micro-case studies;
- baseline instrumentation.

### Channels

- active public requests;
- r/AskSwitzerland, r/Zurich and r/Vespa contextual participation;
- Vespa/vehicle clubs;
- direct introductions;
- founder network only where target fit is real.

### KPI

```text
25 real users
20 completed searches
10 WQSS
≥30% useful-result rate
≥5 return/monitoring intents
≥3 referrals/intros
```

`Useful Result Rate` = completed searches producing at least one user-confirmed useful result / total completed searches.

`≥3 referrals/intros` is the minimum Phase A operating target. `≥5` distinct users spontaneously sharing/referring is a stronger organic-advocacy signal, not a replacement for the minimum target.

### GO

- ≥10 WQSS;
- users can explain the value without prompting;
- provider benchmark reaches ≥50% of tested searches with at least 2 useful sources; this is an initial experimental PASS, not proof of complete market coverage;
- no critical source/governance problem.

### STOP/PIVOT

- <5 WQSS after 20 coherent searches;
- users prefer one marketplace and reject aggregation;
- provider benchmark below 40% = FAIL/STOP-PIVOT; 40–49% = INCONCLUSIVE and requires coverage improvement/retest;
- trust cannot be restored with source transparency;
- founder effort per result cannot plausibly fall.

### Learning goal

Is multi-marketplace search painful enough, and can the current product create a useful outcome?

## Phase B — 25→100 real users

**Duration:** days 15–45
**Mode:** repeat the first channel with signal

### Activities

- two search-derived case studies per week;
- weekly search clinic;
- manual saved-search follow-up;
- manual/prototype shareable result/search artifact; any product implementation requires separate Product review;
- 3 active partnerships;
- localized DE/FR/IT message tests;
- 5 public-safe Atlas-derived guides;
- weekly channel scorecard.

### KPI

```text
100 cumulative real users
40 cumulative WQSS
≥20 return/monitoring intents
≥10 referred users
≥3 active partners
one repeatable channel with ≥1 WQSS / 5 founder hours
```

### GO

- at least one channel produces qualified users for three consecutive weeks;
- 14-day return/monitoring intent ≥20%;
- share/referral contributes ≥10% of new users;
- coverage gaps are concentrated and actionable.

### STOP

- every channel depends on one-off founder relationships;
- content traffic has no search-start conversion;
- retention remains <10%;
- community access requires spam or rule violations.

### Learning goal

Can one acquisition loop repeat without paid media, and do users have a reason to return?

## Phase C — 100→1,000 real users

**Duration:** approximately months 2–6, conditional on Phase B
**Mode:** amplify measured engine

### Engine options

1. **Search-content engine:** real search → insight → indexed guide → search start.
2. **Monitoring engine:** hard search → saved intent → useful update → return/share.
3. **Partner engine:** club/specialist → member searches → shared result/case → new member.
4. **Referral engine:** useful result → privacy-safe share → recipient search.

Do not run all four at equal intensity. Select the one with the best WQSS per founder hour and use the others as support.

### Activities

- scale only validated case-study clusters;
- establish editorial calendar from demand, not keyword volume alone;
- expand provider coverage where benchmark evidence justifies it;
- formalize partner toolkit;
- automate monitoring only after manual demand;
- Product Hunt or Show HN as event distribution, not primary engine;
- test second vertical only after beachhead retention is stable.

### KPI

```text
1,000 cumulative real users
300 cumulative WQSS
≥25% monthly active searchers or monitoring users
≥20% new users from referral/share/partner loops
one organic cluster producing qualified searches weekly
no paid advertising dependency
```

### GO to monetization testing

- repeat use or monitoring intent is proven;
- at least 50 users have received two or more useful outcomes;
- users identify a premium value: faster monitoring, broader permitted coverage, advanced filters or professional workflow;
- willingness-to-pay interviews follow experienced value.

### STOP scaling

- WQSS/user declines as traffic grows;
- source freshness or quality falls;
- provider/governance boundaries become ambiguous;
- content scale creates thin/duplicated pages;
- support burden grows faster than successful searches.

## Operating authority

This Roadmap is the canonical authority for phase targets, phase transitions, GO/STOP/PIVOT gates and the operating calendar. Supporting Growth documents may summarize these decisions but must not maintain a competing numeric calendar.

## 30-day operating calendar

### Week 1

- 10 interviews;
- 5 concierge searches;
- message test;
- coverage benchmark begins;
- 5 club/specialist contacts.

### Week 2

- 10 more searches;
- 2 case studies;
- first search clinic;
- trust/provenance test;
- first GO/STOP review.

### Week 3

- repeat best community source;
- launch manual monitoring follow-up;
- 2 partner pilots;
- 2 more case studies;
- shareable result prototype only; no production share feature is authorized by this Roadmap.

### Week 4

- reach 25 real users;
- calculate WQSS and return intent;
- publish first public-safe marketplace guide;
- decide beachhead GO/PIVOT/STOP;
- select one Phase B channel.

## Resource budget

```text
Paid advertising = 0 CHF
Founder research/outreach = 20–25 h/week initially
Content = 1–2 evidence-backed pieces/week
Small infrastructure cost = allowed only if it reduces measured manual work
```

Every non-zero cost must record expected value and a zero-cost alternative.

## Final principle

Do not scale attention before proving useful searches. Do not automate a behavior users do not repeat. Do not publish Atlas material merely because it can rank. The first growth engine is earned utility.
