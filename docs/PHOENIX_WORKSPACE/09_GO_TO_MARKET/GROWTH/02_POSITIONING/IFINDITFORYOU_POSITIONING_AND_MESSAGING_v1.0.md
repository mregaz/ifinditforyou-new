# IFINDITFORYOU POSITIONING AND MESSAGING v1.0

## 1. Recommended category

**Multi-marketplace finding assistant**

Non usare come categoria primaria:

- “search engine”: crea confronto diretto con Google e promette ampiezza infrastrutturale;
- “AI shopping assistant”: è generico e sposta l’attenzione sulla tecnologia;
- “deal finder”: restringe il valore al prezzo;
- “personal shopper”: suggerisce raccomandazione/decisione delegata;
- “discovery engine”: poco comprensibile in cinque secondi;
- “search agent”: utile a un pubblico tecnico ma ancora ambiguo su autonomia e coverage.

## 2. Five-second message

### Winner candidate

**Describe it once. We search the marketplaces you would otherwise check one by one.**

Support:

**For hard-to-find, used and rare items. Results keep their source, time and limits visible.**

CTA:

**Start a search**

### Localized variants

**IT**

Do not claim “all marketplaces”, “best price”, “complete market” or “we always find it” unless proven for the exact search.

## 3. Message hierarchy

1. **Problem:** the same search is fragmented across many sources.
2. **Outcome:** describe once and receive organized, source-linked results.
3. **Use case:** hard-to-find, used, rare or discontinued items.
4. **Trust:** visible source, timestamp, coverage and uncertainty.
5. **Action:** run one real search.

## 5. Message tests

| ID | Headline | Hypothesis | Success |
|---|---|---|---|
| M1 | Describe it once. We search the marketplaces… | task compression is clearest | ≥60% correctly explains product after 5 seconds |
| M2 | Stop searching the same item on five different sites. | pain-led message drives search start | +20% search-start vs M1 |
| M3 | Hard to find? Let us look across the right sources. | rarity emotion increases relevance | more qualified rare-item queries |
| M4 | Your multi-marketplace search assistant. | category label improves recall | ≥40% recalls “multi-marketplace” |
| M5 | Tell us what you’re looking for. We’ll find where it’s hiding. | emotional promise improves interest | reject if perceived as guaranteed |

Run as five-second interviews first, not paid A/B traffic: 5 users per message, randomized order, ask “What does this product do?” and “What do you expect it to search?”

## 6. Objection handling

**Why not Google?**
Google is excellent for broad discovery. iFindItForYou is designed for one structured request across relevant marketplaces, especially when used/rare supply is fragmented.

**Why not search each marketplace?**
You can. The value is avoiding repeated setup and organizing results consistently.

**Does it search everything?**
No universal-coverage claim. The product should state which sources were checked and which were unavailable.

**Is the result trustworthy?**
Every result should retain its source and time. Users must verify the live listing and seller; the finder does not guarantee seller authenticity.

**Is this a recommendation engine?**
No. It helps find and organize options; the user decides.

## 8. Positioning guardrails

- Search coverage ≠ market completeness.
- Listing availability ≠ seller legitimacy.
- Result ordering ≠ recommendation.
- Lower price ≠ best purchase.
- High confidence ≠ truth.
- AI interpretation ≠ autonomous purchasing.
- Atlas intelligence ≠ public permission to reproduce internal material.

## Final positioning decision

```text
CATEGORY = Multi-marketplace finding assistant
PRIMARY PROBLEM = Repeating one hard search across fragmented sources
PROMISE = Describe once; inspect organized source-linked results
FIRST USE CASE = Swiss used Vespa/scooter/enthusiast motorcycles
TRUST MECHANISM = Source + timestamp + coverage + explicit unknowns
PROHIBITED CLAIM = Search everywhere / guaranteed find / always best price
```
